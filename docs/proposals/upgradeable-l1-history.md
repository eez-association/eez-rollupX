## Scope and requirements

Adopt [issue #113](https://github.com/eez-association/eez-rollupX/issues/113):
an initially empty store of strictly increasing positive L1 block-number/hash
pairs, allowing gaps. Install it behind the pinned `EEZProxy` at
`0xeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee0077`. Its initial implementation is
`0xeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee007a`; its dedicated ProxyAdmin is
`CREATE(history, 1)` (`0x58aD165846a897f4aba3EC8f07a4a7dB434324Bf`). The existing
`EEZ_L2_UPGRADE_OWNER` owns that admin initially, as it does EEZL2's separate
admin. No new configuration input or core-contract change is needed.

| ID | Required behavior | Acceptance |
| --- | --- | --- |
| H1 | Only the ProxyAdmin owner can upgrade; ownership can be transferred. | Unauthorized upgrade/direct proxy calls fail; authorized upgrade and ownership transfer succeed. |
| H2 | Empty history returns zero. Imports are system-only, nonempty, increasing, nonzero and atomic; gaps cannot be backfilled. | Exact issue #113 contract tests, including boundaries and rollback. |
| H3 | Genesis binds proxy, initial implementation, admin and authority, with empty application storage. | Exact generated bytes, nonces and storage; malformed genesis rejection; deterministic regeneration. |
| H4 | Composer, followers and offline signer execute the implementation authenticated by L2 state. | Real upgrade transaction, preserved records, subsequent import and independent DA/witness replay. |
| H5 | Native history still enforces scheduling, 64-record and gas bounds, authenticated ancestry, and synchronized PREVRANDAO. | Positive bootstrap, sparse imports, missing/incorrect evidence, omission and signing regressions. |
| H6 | All producers/consumers use explicit pairs and the current validation identity, without legacy fallbacks. | RLP/ABI/JSON, DA and proving conformance tests; unchanged `prove.v2` schema. |

## Design and trust

The implementation needs no constructor or initializer. Slot zero is the
`mapping(uint64 => bytes32)` and slot one is the latest imported `uint64`.
Genesis installs only ERC-1967 pointers in proxy storage. The standalone
implementation is also empty. The proxy creates its dedicated ProxyAdmin using
its existing empty-data constructor; no duplicate proxy implementation is needed.

The public store and the execution origin are distinct before the first import.
Queries return `(0, 0)` or a zero hash. Execution inherits the authenticated
`config.rollupX.l1Reference`, including its PREVRANDAO. The first optional update
may include that reference if its number is positive; block zero is never stored.
Subsequent updates must advance past the stored endpoint. No update may regress
below the genesis reference. Omission remains valid indefinitely.

The native body becomes `0x46 || RLP([1, chainId, [[number, blockHash], ...]])`.
The default producer fills consecutive available numbers, up to 64. Replay also
accepts gaps, authenticating each pair through the complete linked L1 headers
and enforcing the delayed cutoff on the final pair. Skipped records are not
implicitly stored and cannot be backfilled. An import remains optional and
restricted to transaction zero at an eligible timestamp. Timing and bounds are
execution rules, not storage or checks in the proposed Solidity contract.

Execution pins the proxy's code, including its immutable admin. The EVM resolves
the implementation from witnessed state. The network profile commits to the proxy runtime; the genesis block also commits
to the initial implementation and admin owner. Upgrades are ordinary signed L2 transactions. Historical replay
uses the historical implementation and never substitutes current code or asks a
chain RPC which implementation to trust.

As with EEZL2, the upgrade owner is trusted with contract behavior. A proof
establishes execution of the selected code, not correctness of arbitrary future
code. Compatible implementations must preserve slots 0/1 and query semantics,
system-only append semantics, bounded gas, and no output or logs from native
imports. Changing execution rules needs a coordinated release; upgrading a proxy
does not override node validation. The two admins have independent ownership
and can be transferred separately.

## Compatibility and validation

This introduced validation contract 6 and new genesis hashes. The current
[Core Rollup integration](rollupx-manager-simplification.md) uses validation
contract 7 while retaining this history layout. The history ABI, storage and native `0x46` body change together. All roles
must use matching genesis and binaries. There is no migration, old selector or
encoding fallback, or support for mixed identities. `prove.v2`, cross-chain
`0x45`, core contracts and the protocol pin remain unchanged. The prover remains
without L1 or L2 RPC. Future compatible implementation upgrades need no binary
change. Rolling back an upgrade is safe only if the old implementation understands
the resulting storage; changing the code pointer cannot undo storage changes.

The normative contract is [L1_HISTORY_SPEC.md](../../contracts/L1_HISTORY_SPEC.md).
Run contract authorization/storage tests, genesis checks, affected Rust/signer
tests, conformance fixtures and source-based upgrade/replay tests. The complete
release/Kurtosis matrix remains a CI gate. This PR does not deploy contracts or
restart an existing network.

Local results, corrected first failures and unexecuted CI/operational checks are
recorded in the [implementation audit](../audits/2026-10-27-upgradeable-l1-history/README.md).
