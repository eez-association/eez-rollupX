## F2 — Closed at the type boundary as written

`run_settlement_with_observations` now returns `settlement::RecomputedPublicInputsHash`; the only `AttestablePublicInputsHash(...)` constructor expression is in `validate_and_settle`, after `verify_observations` succeeds and after a further cancellation and deadline check. Because the tuple field is private to `settlement_job`, no code in `service.rs`/`rpc.rs` can construct the type, and `AttestationMaterial` cannot be built without one. `run_settlement` returns the non-attestable digest and asserts empty observations — correct pattern. No new signing route is introduced: `into_inner` only unwraps an already-authorized value.

Residual: any `#[cfg(test)] mod tests` declared inside `settlement_job.rs` can see the private field; keep tests off direct construction. Error mapping is right (`ObservationReplay` → `FailedPrecondition`, gate `observation_replay`). The discriminating test (lookup-only inbound entry with forged `expected_output` → `FailedPrecondition`, `signing_calls() == 0`) is not among the four listed tests and is still required.

## F3 — Closed, fail-closed, strictly earlier

Returning `ValidationError::Rejected` from the reconstruction branch is equivalent to the prior end-to-end behaviour for every accepted request (every v3 position needed a fact anyway) and better for availability: the window stops at the first non-reproducible block instead of executing the rest and failing in settlement. `reconstruction_input` is still cloned before `std::mem::take(&mut admitted.witness)`; `admitted.rlp` survives the take. Test stubs with `derivation_enabled = false` still yield `None`, so the `MissingReconstruction` DA test remains meaningful; in production that variant is now unreachable but harmless.

Two minor notes: the public message moves from "settlement validation rejected" to "window validation rejected" and `PipelineError::gate()` reports `execution` for this case — a distinct label would help operators separate reconstruction drift from Stateless rejections. Confirm the reconstruction error's `Display` does not embed block/witness bytes, since it now reaches WARN.

**BPO assertion: withdrawn.** My claim that an L2 document with BPO forks would produce `SpecId::BPO*` and be rejected by the `next_attributes` allowlist was not grounded in the pinned selector, which was not in the snapshot. Given your reading that alloy-evm 0.34.0 selects Osaka for BPO timestamps and the passing real-signer BPO1/BPO2 acceptance, the assertion is wrong and the recommended BPO exclusion is withdrawn. The remaining BPO risk is not fork identity but blob-parameter schedule agreement between the assembler's next-block env and Stateless's header validation at a BPO boundary; a block whose parent blob usage makes `excess_blob_gas` differ between Osaka and BPO1 parameters would discriminate. If both sides read the same `ChainSpec` blob schedule, this is a shared-source concern only.

## Header gas-limit occupancy

**Reachable under the supplied code and consensus rules: yes, and without the window.** Because the parent header is authenticated only against `parent_hash` and the witness pre-state root, a caller can fabricate a parent with any `gas_limit` (up to reth's 2^63−1 header sanity bound, if present in the pinned version) and a private state containing a funded sender and a looping contract. Consensus then permits a first block within ±1/1024 of that value. The 1/1024 climb over 65,536 blocks is therefore not needed; it would only matter if a future L1-canonical parent anchor were added — at which point the climb would defeat the anchor, so an anchor alone would not be a fix.

**What bounds the work:** within one block, EVM work ≤ block `gas_limit` (the executor rejects a transaction whose gas limit exceeds remaining block gas before running it, so Σ consumed ≤ header limit). Nothing else bounds it: byte/item/count quotas bound encoding size, not gas; the deadline and cancellation are checked only between blocks; observation replay re-executes the terminal block a second time, also non-interruptibly. Under Osaka the 2^24 per-transaction cap forces many transactions, but a few thousand ~110-byte OOG-loop transactions (~400 KB) carry ~6×10¹⁰ gas, and the attacker computes nonce/balance/receipt outcomes analytically. Pre-Osaka one transaction suffices. So the existing exposure is: one request can hold the single slot (and block `wait_until_idle`) for an EVM-time duration set by the caller, far beyond 600 s, at negligible cost to the caller. Endpoint access control is the only current defense.

**Soundness:** unaffected. Every such block is valid or rejected exactly as consensus dictates; the settlement gates and the L1-root binding run unchanged; an invalid settlement still cannot sign.

**Does raising the window change it:** no. Stall time is one block's execution plus the second terminal replay; between-block cancellation already bounds the per-block count. Under the fabricated-parent route the window count is irrelevant.

**Repair:** this is not a hypothesis-only recommendation — the absence of any gate between encoded size and EVM work is visible in the code, and the cost-to-attacker asymmetry is structural. A bounded operational per-block header `gas_limit` ceiling, checked in `decode_and_match_stream_metadata` (the first point the header is decoded, before that block's replay; the settling block is decoded up front), is the localized, correct lever: it caps EVM work per non-interruptible stretch, implicitly caps transaction count (≥21,000 gas each), and needs no knowledge of the window or the parent. It should be a producer-facing capability (the composer already derives `gas_limit` through `next_attributes`, so an over-ceiling chain is a configuration error, not a protocol dispute) and separate from protocol validity — reject with `FailedPrecondition` and its own gate label. Default to a small multiple of the deployment's target. A Σ transaction `gas_limit` bound is subsumed by this and adds nothing.

**Discriminating tests:** (1) single-block window with a self-consistent fabricated parent whose `gas_limit` exceeds the ceiling → `FailedPrecondition`, zero Stateless executions (assert via the test backend's execution counter or elapsed time), `signing_calls() == 0`; the same window at exactly the ceiling → accepted. (2) An `#[ignore]` benchmark establishing the existing exposure: fabricated parent, one pre-Osaka OOG-loop transaction at 10⁹ gas (or ~100 Osaka-capped ones); assert wall time exceeds a chosen threshold and that setting the cancellation token mid-block does not stop it. This is the evidence that converts the analysis above from reasoned to measured, and it doubles as the regression guard for the ceiling.
