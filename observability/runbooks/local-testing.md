# Single-machine Compose testing

The current milestone is a usable local test setup. Run the monitoring services,
observer and PostgreSQL on one Linux Docker host. Separate monitoring hosts,
independent heartbeat delivery, off-host recovery and production calibration are
follow-ups, not prerequisites for this milestone. Local backups share the host's
failure domain. Performance comparisons remain deferred at the user's request.

## Try the dashboards with simulated data

Use the verified node image from the local runtime producer; it contains the
observer. The following test starts an isolated Compose project, migrates its
database, checks ingestion and dashboards, and leaves the healthy setup running
for inspection:

```bash
python3 observability/tests/smoke-single-host.py \
  --image "$EEZ_NODE_IMAGE" \
  --runtime .runtime/observability-local \
  --keep
```

The command prints the local Grafana URL and the password-file location, plus
the exact stop command. Data comes from the repository's deterministic RPC
fixture, not Chiado or another live chain. Missing lifecycle, blob or trace
evidence remains unknown. Omit `--keep` for an automated test that cleans up its
own project. Keep the runtime directory private; it contains generated database
and Grafana credentials. A nonempty runtime directory is not overwritten.

## Connect your local EEZ deployment

Use the same image and Compose overlay with verified chain inputs. The observer
requires the PR26-compatible node RPC and schema22; this procedure does not
upgrade or reset an existing chain.

1. Copy [stack.local.example.json](../stack.local.example.json) to a private file.
   Set its dedicated log directory and deployment labels. Alerts are explicitly
   paused with `alerting_enabled: false`; no webhook receivers are needed.
2. Run `prepare.py` and copy [indexer.example.json](../indexer.example.json) into
   the generated runtime directory. Fill the verified RPC/chain/genesis,
   rollup/contract, bootstrap and receipt-selection fields. Keep
   `database_config` set to `writer.json`.
3. Set the indexer's exporter listener to `0.0.0.0:19100` with
   `allow_non_loopback: true`. This is inside the observer container; the overlay
   publishes no observer port. Prometheus scrapes `observer:19100` over the
   private Compose network. Container-specific database files generated by
   `prepare.py` connect to `postgres:5432` over the internal ledger network.
4. Set RPC URLs to reachable Docker service names and container ports, not host
   loopback addresses. If your nodes run in another Compose project, include
   [compose.node-network.yaml](../compose.node-network.yaml) and set
   `EEZ_NODE_NETWORK` to their existing network name. This attaches only the
   observer to that network and does not replace or restart the nodes.

```bash
python3 observability/prepare.py \
  --config /path/to/private/local-stack.json \
  --runtime .runtime/observability

export OBS_OBSERVER_UID="$(id -u)"
export OBS_OBSERVER_GID="$(id -g)"
export OBS_INDEXER_CONFIG="$PWD/.runtime/observability/indexer.json"
export OBS_LIFECYCLE_DIR="$PWD/.runtime/observability/lifecycle"
mkdir -p "$OBS_LIFECYCLE_DIR"

compose=(docker compose --project-name eez-observability
  --env-file .runtime/observability/compose.env
  -f observability/compose.yaml -f observability/compose.observer.yaml
  --profile database)

# If the nodes use another Compose network, also add this file to the array:
# -f observability/compose.node-network.yaml
# and export EEZ_NODE_NETWORK with the existing network name.
"${compose[@]}" config --quiet
"${compose[@]}" up -d --wait postgres
"${compose[@]}" run --rm observer-migrate
"${compose[@]}" up -d --wait
"${compose[@]}" logs --tail 30 observer
"${compose[@]}" ps
```

Set `EEZ_NODE_IMAGE` to the verified image before these commands. The overlay
uses the existing local image and never rebuilds or pulls a mutable replacement.
The observer runs as your configured numeric UID/GID, with read-only configuration
and lifecycle mounts. Only the explicit migration service gets administrator
credentials; continuous indexing gets the writer connection file. Missing bind
paths fail rather than creating empty replacement directories.

If native lifecycle capture is enabled, use its actual readable spool directory
for `OBS_LIFECYCLE_DIR` and `/lifecycle` paths in the indexer configuration. An empty
directory with `lifecycle: []` supports receipt indexing without claiming native
request history. Avoid running a second exporter on the observer's metrics port.

Open Grafana at `http://localhost:19300` using `admin` and the password in
`.runtime/observability/secrets/grafana-admin-password`. Inspect collection
freshness and coverage alongside values. Stop and resume without deleting data:

```bash
"${compose[@]}" stop
"${compose[@]}" up -d --wait
```

Use `down` to remove the containers while preserving named volumes. Only use
`down --volumes` when intentionally discarding this test database and history.
The [restore procedure](restore.md) also works with a private local backup
directory; off-host copies can be added later.

## Enable notifications when useful

Set `alerting_enabled: true` and provide the normal webhook URLs to enable
notifications. A same-host receiver is suitable for functional testing but
cannot independently detect loss of the host. Re-run `prepare.py` and restart
Grafana to apply the generated provisioning. Disabled mode pauses EEZ rules and
does not reset unrelated contact points or routing. Keep the generated runtime
when toggling this setting so prior optional EEZ rules can also be paused.
